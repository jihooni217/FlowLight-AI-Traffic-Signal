# data/ — 교통량 입력 데이터

이 폴더의 파일은 `app/traffic_data.py` 가 읽어 **정규화 프로파일**로 바꾼다.
프로파일의 값은 모두 *입력 수요*(대/시)와 그로부터 계산한 *차량 발생률*(차로당 대/초)이며,
현재 대기 차량 수(queue)는 시뮬레이션이 계산한 결과라 이 폴더에는 존재하지 않는다.

| 용어 | 의미 | 어디서 나오나 |
|---|---|---|
| `volume_per_hour` | 실제 입력 수요 (대/시) | 공공 데이터 |
| `arrival_rate_per_sec` | 시뮬레이터 차량 발생률 (차로당 대/초) = `volume / lanes / 3600` | `traffic_data.py` |
| `queue` | 현재 대기 차량 수 | 시뮬레이션 결과. **이 폴더와 무관** |

## 파일

| 파일 | 내용 |
|---|---|
| `sample_seoul_traffic_history.csv` | 데모용 **합성 예제**. 컬럼 구조는 아래 실제 데이터셋과 동일 |
| `sample_seoul_traffic_history.meta.json` | 위 CSV 를 읽는 방법(지점→접근로 매핑, 날짜, 유입/유출 선택, 출처) |

## 데이터가 흘러가는 길

1. `app/traffic_data.py` 의 `load_profile_from_meta()` 가 메타 파일을 읽어 `TrafficProfile` 로 정규화한다.
   접근로 합계(대/시)와 차로 수를 구하고, `volume / lanes / 3600` 으로 차로당 발생률(대/초)을 만든다.
2. `GET /api/traffic/profile` 이 이 프로파일을 JSON 으로 내보낸다. 환경 변수 `TRAFFIC_PROFILE_META` 로 다른 메타 파일을 지정할 수 있다.
3. 프론트의 *실데이터 프로파일* 모드가 이 응답을 받아 3x3 격자의 N/S/E/W 진입로에 접근로별 발생률로 Poisson 도착을 만든다.
4. 시뮬레이터가 계산한 접근로별 `queue`·대기시간·도착·포화도는 `queues.by_approach` 로, 입력 수요는 `demand` 로 **따로** AI 에 전달된다.

샘플의 08시 값이 어떻게 변환되는지 (검증된 값):

| 접근로 | 수요 (대/시) | 차로 | 발생률 (차로당 대/초) |
|---|---|---|---|
| N | 842 | 3 | 0.077963 |
| S | 790 | 3 | 0.073148 |
| E | 610 | 2 | 0.084722 |
| W | 655 | 2 | 0.090972 |

시뮬레이터의 포화유출률은 0.5대/초(1800대/시/차로)이므로, 차로당 값을 넣어야 v/c 비율이 현실과 같은 스케일이 된다.
842 를 그대로 넣으면 3배 과대 수요가 된다.

## 원본 데이터셋 (컬럼 구조의 출처)

- 이름: 서울특별시_교통량 이력 정보
- 제공: 서울특별시 (원천 시스템 TOPIS, https://topis.seoul.go.kr)
- 위치: 공공데이터포털 https://www.data.go.kr/data/15056899/openapi.do
- 이용허락범위: 포털 표기상 "제한 없음", 무료 (2026-09-10 확인)
- 출력 항목: `지점번호`, `년월일`, `시간`, `유입유출 구분`, `차로번호`, `교통량`

실제 데이터는 API 키가 필요해 이 저장소에는 포함하지 않았다. 아래 절차로 교체할 수 있다.

## 원본 컬럼 → 정규화 매핑

| 원본 컬럼 (공백 무시) | 정규화 이름 | 처리 |
|---|---|---|
| `지점번호` | `site_id` | `site_to_approach` 로 N/S/E/W 접근로에 매핑. 매핑에 없는 지점은 무시 |
| `년월일` | `date` | `YYYYMMDD`. 여러 날짜가 섞이면 `date` 로 하루 선택 |
| `시간` | `hour` | 0~23 정수. `"08"`, `"8시"` 허용 |
| `유입유출 구분` | `flow_type` | `flow_type`(기본 `유입`)과 같은 행만 사용 |
| `차로번호` | `lane_no` | 접근로별 차로 수 = 차로번호 종류 수 (`lanes` 로 덮어쓰기 가능) |
| `교통량` | `volume` | 차로별 값을 접근로 합계로 더함 (대/시) |

주의할 가정 두 가지.
1. 이 데이터의 "지점"은 도로 **단면**이라 교차로 하나를 표현하려면 지점 4개(접근로당 1개)가 필요하다.
2. 원본의 유입/유출은 제공자 기준(도심 방향 등)이라, 어느 값을 "교차로로 접근하는 교통"으로 볼지는
   `meta.json` 의 `flow_type` 으로 사용자가 정한다.

접근로 명명: `N` 은 **북측에서 진입해 남쪽으로 향하는** 차량이다 ("북행"이 아니다).

## 합성 예제의 생성 공식 (재현 가능)

- 날짜 `20250514`(수요일), 지점 4개: `DEMO-N`(3차로, 첨두 842), `DEMO-S`(3차로, 790), `DEMO-E`(2차로, 610), `DEMO-W`(2차로, 655)
- 시간대 계수 `F[h]` (h = 0..23):
  `0.10 0.06 0.04 0.03 0.04 0.10 0.30 0.75 1.00 0.80 0.65 0.65 0.70 0.68 0.66 0.70 0.80 0.95 0.90 0.70 0.55 0.45 0.30 0.18`
- 유입 접근로 합계 `V_in(h) = round(첨두 × F[h])`, 유출 `V_out(h) = round(V_in(h) × 0.85)` (유출 행은 로더가 버린다)
- 차로 분배: `V // lanes` 를 기본으로 하고 나머지를 앞 차로부터 1대씩 더한다
- 따라서 08시 유입 합계는 정확히 N 842 / S 790 / E 610 / W 655 이다

## 실제 데이터로 교체하는 방법

1. 공공데이터포털에서 위 데이터셋을 받아 CSV 로 저장한다. 인코딩이 `cp949` 이면 `meta.json` 의 `encoding` 을 바꾼다.
2. 교차로의 접근로 4개에 해당하는 `지점번호` 4개를 찾아 `site_to_approach` 에 적는다.
3. 재생할 날짜를 `date` 에 적고, 차로 수를 데이터로 세지 않으려면 `lanes` 에 직접 적는다.
4. `source`, `license` 를 실제 출처로 바꾼다.
